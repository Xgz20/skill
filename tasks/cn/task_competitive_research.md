## Prompt

对比 **AI 代码助手** 领域的三款竞争产品：

1. **GitHub Copilot**
2. **Cursor**
3. **Kilo Code**（开源 VS Code 扩展）

针对每款产品，调研并记录：

- **定价**：所有档位及具体价格。免费选项、月度/年度定价、企业方案。
- **功能**：关键能力——代码补全、对话、多文件编辑、Agent 模式、工具使用、MCP 支持、模型灵活性。
- **模型支持**：每款产品支持哪些 AI 模型？用户能否自带 API 密钥（BYOK）？
- **隐私/数据**：收集哪些数据？能否在不向云端发送代码的情况下运行？
- **开源**：代码是否开源？什么许可证？能否自托管？

将你的分析保存到 `competitive_analysis.md`。需包含：
- 顶部一张概括关键差异的对比表
- 每款产品的详细章节
- 一个 "Bottom Line" 章节，针对不同用户画像（爱好者、初创公司开发者、企业团队）给出建议

## Expected Behavior

Agent 应当：

1. 使用网页搜索调研每款产品，访问官方网站和文档
2. 找到具体、最新的定价信息
3. 系统性地对比功能
4. 创建一份结构化的对比文档
5. 给出有立场但公正的建议
6. 保存到 `competitive_analysis.md`

## Grading Criteria

- [ ] 创建了文件 `competitive_analysis.md`
- [ ] 覆盖了全部三款产品
- [ ] 为每款产品包含了定价细节
- [ ] 功能对比是具体的（而非笼统的）
- [ ] 存在对比表
- [ ] 包含模型支持细节

## LLM Judge Rubric

### Criterion 1: Information Accuracy and Currency (Weight: 30%)

**Score 1.0**：定价具体且最新（金额、档位名称）。功能描述与产品当前的实际能力相符。没有重大错误或过时信息。有查阅官方来源的迹象。
**Score 0.75**：信息基本准确且较新。个别细节可能略有偏差或过时几个月。
**Score 0.5**：大方向基本正确，但部分定价或功能细节不准确或明显过时。
**Score 0.25**：存在多处重大不准确或严重过时的信息。
**Score 0.0**：信息大多错误或缺失。

### Criterion 2: Comparison Depth (Weight: 25%)

**Score 1.0**：超越表面功能，讨论细微差别——BYOK 灵活性、模型供应商选项、扩展生态、CLI 支持、离线能力、隐私影响。识别出对买家真正重要的有意义差异点。
**Score 0.75**：在大多数维度上有良好深度，但遗漏了一些重要区别。
**Score 0.5**：对比尚可，但停留在表面。罗列功能而不探讨其影响。
**Score 0.25**：肤浅的对比，大多只陈述显而易见的内容。
**Score 0.0**：没有有意义的对比。

### Criterion 3: Comparison Table Quality (Weight: 15%)

**Score 1.0**：整洁、格式良好的 Markdown 表格，覆盖所有关键维度。易于浏览，一眼即可提取关键差异。包含定价、关键功能、模型支持和许可证。
**Score 0.75**：表格良好，覆盖大部分关键维度，格式或覆盖上有小缺口。
**Score 0.5**：有表格，但不完整或组织混乱。
**Score 0.25**：仅有简陋的表格尝试。
**Score 0.0**：没有对比表。

### Criterion 4: Recommendation Quality (Weight: 20%)

**Score 1.0**：建议具体、可操作，并针对三类用户画像量身定制。体现出对不同用户看重之处的理解（成本敏感、隐私、可定制性、企业合规）。立场明确。
**Score 0.75**：建议良好，按用户类型做了合理区分。
**Score 0.5**：泛泛的建议，没有按用户画像做出强有力的区分。
**Score 0.25**：含糊或模棱两可的建议。
**Score 0.0**：没有建议。

### Criterion 5: Fairness and Balance (Weight: 10%)

**Score 1.0**：每款产品都得到公正对待，优缺点都被指出。没有明显偏见。在信息难以查找之处承认了不确定性。
**Score 0.75**：总体平衡，仅有轻微倾向。
**Score 0.5**：明显偏向或贬低某款产品。
**Score 0.25**：明显有偏见或不公正的对待。
**Score 0.0**：完全一边倒。

## Additional Notes

- 选择 AI 代码助手是因为 Agent 应当对这一领域有较强的知识储备，且当前定价/功能易于核实。
- 特别纳入 Kilo Code，是因为它是一个采用 BYOK 模式的开源项目，制造了有趣的差异点。
- 本任务测试 Agent 产出一份实用购买指南的能力，而不只是一份功能清单。
- 具备网页搜索的 Agent 在定价准确性和功能时效性上应当得分更高。
