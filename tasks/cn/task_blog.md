## Prompt

撰写一篇约 500 字、主题为"远程办公对软件开发者的好处"的博客文章。将其保存到 blog_post.md。

## Expected Behavior

Agent 应当：

1. 创建一篇结构完整的博客文章，包含引言、正文和结论
2. 聚焦于专门针对软件开发者的好处
3. 篇幅控制在约 500 字（400-600 字可接受）
4. 使用规范的 markdown 格式
5. 将内容保存到名为 `blog_post.md` 的文件中

文章应当引人入胜、内容翔实、行文专业。应覆盖多项好处，并提供论证或示例。

## Grading Criteria

- [ ] 已创建文件 `blog_post.md`
- [ ] 内容约为 500 字（400-600 字区间）
- [ ] 文章结构清晰（引言、正文、结论）
- [ ] 内容聚焦于软件开发者的好处
- [ ] 行文清晰且引人入胜
- [ ] 使用规范的 markdown 格式
- [ ] 覆盖多项不同的好处
- [ ] 为论点提供论证或示例

## LLM Judge Rubric

### Criterion 1: Content Quality and Relevance (Weight: 30%)

**Score 1.0**: 内容高度贴合软件开发者，覆盖 4 项以上不同的好处，并配有清晰的论证、示例或证据。信息准确且有洞见。

**Score 0.75**: 内容相关，覆盖 3-4 项好处。论证充分。在深度或示例上存在轻微欠缺。

**Score 0.5**: 内容切题，但仅覆盖 2-3 项好处。提供了一些论证，但缺乏深度或对软件开发者的针对性。

**Score 0.25**: 内容笼统，或仅浅显地覆盖 1-2 项好处。对软件开发者的针对性有限。

**Score 0.0**: 内容跑题、缺失，或完全未涉及远程办公的好处。

### Criterion 2: Structure and Organization (Weight: 25%)

**Score 1.0**: 结构优秀，引言清晰、正文段落组织良好、结论有力。思路衔接逻辑顺畅。恰当使用标题与 markdown 格式。

**Score 0.75**: 结构良好，具备引言、正文与结论。存在轻微的组织问题。markdown 格式尚可。

**Score 0.5**: 具备基本结构，但存在明显的组织问题。过渡薄弱或思路不清晰。markdown 格式很少。

**Score 0.25**: 结构较差。缺少关键章节（引言或结论）。内容杂乱无章。

**Score 0.0**: 没有可辨识的结构。内容混乱或缺失。

### Criterion 3: Writing Quality (Weight: 20%)

**Score 1.0**: 写作优秀，行文清晰、引人入胜。语气专业。没有明显的语法或拼写错误。句式富于变化。

**Score 0.75**: 写作质量良好，存在轻微问题。总体清晰且专业。语法错误较少。

**Score 0.5**: 写作尚可，但在清晰度、语气或语法上存在明显问题。部分措辞别扭。

**Score 0.25**: 写作质量较差。存在多处语法错误、措辞不清或语气不专业。

**Score 0.0**: 写作无法理解或缺失。

### Criterion 4: Word Count Compliance (Weight: 15%)

**Score 1.0**: 字数为 450-550 字（在目标值 10% 以内）。

**Score 0.75**: 字数为 400-600 字（在目标值 20% 以内）。

**Score 0.5**: 字数为 300-400 字或 600-700 字（偏离目标值 20-40%）。

**Score 0.25**: 字数为 200-300 字或 700-800 字（偏离目标值 40-60%）。

**Score 0.0**: 字数低于 200 字或超过 800 字，或内容缺失。

### Criterion 5: Task Completion (Weight: 10%)

**Score 1.0**: 已创建文件且文件名正确（blog_post.md），包含完整的博客文章，满足所有要求。

**Score 0.75**: 已创建文件，但文件名有轻微问题，或遗漏一项小要求。

**Score 0.5**: 已创建文件，但遗漏多项要求或存在重大问题。

**Score 0.25**: 已创建文件，但内容不完整或严重欠缺。

**Score 0.0**: 未创建文件，或文件为空/无法使用。
