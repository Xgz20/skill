## Prompt

请找到 5 个即将举行的科技会议，并创建 events.md 文件，为每个会议列出名称、日期、地点和网站。

## Expected Behavior

Agent 应当：

1. 使用网络搜索或调研工具找到真实的科技会议
2. 识别今年即将举行的 5 个会议
3. 提取关键信息：名称、日期、地点、网站
4. 创建名为 `events.md` 的文件，包含这些信息
5. 格式清晰且一致
6. 确保会议真实且信息准确

Agent 可以使用多种搜索策略，并应从可靠来源验证信息。

## Grading Criteria

- [ ] 已创建文件 `events.md`
- [ ] 包含恰好 5 个会议条目
- [ ] 每个条目都有会议名称
- [ ] 每个条目都有日期信息
- [ ] 每个条目都有地点信息
- [ ] 每个条目都有网站/URL
- [ ] 信息看起来准确且可验证
- [ ] 格式清晰且一致

## LLM Judge Rubric

### Criterion 1: Information Accuracy (Weight: 35%)

**Score 1.0**：全部 5 个会议都是真实的、可验证的科技会议。所有信息（名称、日期、地点、网站）准确且可验证。没有虚构的活动。

**Score 0.75**：4-5 个会议可验证且信息准确。日期或细节有少量错误，但不影响整体有效性。

**Score 0.5**：3-4 个会议可验证。部分信息可能过时或包含错误，但活动是真实的。

**Score 0.25**：仅 1-2 个会议可验证，或多个条目包含重大错误。可能包含虚构的活动。

**Score 0.0**：全部或大部分会议看起来是虚构的，或信息完全不准确。

### Criterion 2: Completeness (Weight: 25%)

**Score 1.0**：全部 5 个会议都有完整信息：名称、具体日期（不只是月份）、地点（城市/国家）以及可用的网站 URL。

**Score 0.75**：全部 5 个会议存在，且信息基本完整。有少量缺失（例如近似日期、缺少具体场地）。

**Score 0.5**：4-5 个会议存在，但有明显的信息缺失。部分条目缺少日期、地点或网站。

**Score 0.25**：少于 4 个会议，或多个条目有重大信息缺失。

**Score 0.0**：少于 3 个会议，或大部分条目严重不完整。

### Criterion 3: Relevance and Quality (Weight: 20%)

**Score 1.0**：全部会议都是重要的、知名的科技会议（例如主要行业活动、成熟的会议系列）。主题或地区有良好的多样性。

**Score 0.75**：大部分会议是知名的科技活动。选择良好，重要性或多样性方面有小问题。

**Score 0.5**：知名与较小会议混合。多样性有限，或与"科技"的相关性存在疑问。

**Score 0.25**：大多是不知名或可疑的会议。与科技行业相关性差。

**Score 0.0**：会议与科技无关或完全不合适。

### Criterion 4: Formatting and Presentation (Weight: 15%)

**Score 1.0**：格式优秀，结构一致。有效使用了 markdown（标题、列表、链接）。易于阅读且组织良好。

**Score 0.75**：格式良好，有少量不一致。总体清晰易读。

**Score 0.5**：基本格式，但有明显的不一致或组织问题。较难阅读。

**Score 0.25**：格式差。结构不一致导致信息难以解析。

**Score 0.0**：无格式或完全不可读。

### Criterion 5: Task Completion (Weight: 5%)

**Score 1.0**：文件以正确名称（events.md）创建，包含 5 个会议，满足所有要求。

**Score 0.75**：文件创建，有少量问题但基本完整。

**Score 0.5**：文件创建但缺少重要要求。

**Score 0.25**：文件创建但严重不足。

**Score 0.0**：未创建文件或文件为空。
