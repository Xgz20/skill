# Agent 能力维度与子能力定义

## 概述

本文档定义了 PinchBench 评测体系中 Agent 能力维度的完整分类，包括每个维度的标签、中文名称和子能力细分。用于指导评测集设计时对任务进行能力标注。

## 能力维度框架（六层结构）

```
Agent 能力全景
├── 基础能力（底层通用能力，作为其他能力的实现底座）
│   ├── 指令遵循与约束理解
│   ├── 上下文记忆与状态管理
│   ├── 输出格式适配
│   ├── 幻觉抑制
│   └── 工具调用
├── 感知能力（获取和理解输入信息）
│   ├── 多模态感知
│   ├── 数据提取与处理
│   └── 信息检索与综合
├── 认知能力（思考和推理）
│   ├── 多步推理
│   ├── 规划与任务分解
│   └── 领域推理
├── 执行能力（与外部世界交互）
│   ├── 代码生成与理解
│   ├── 外部服务集成
│   └── 自然语言生成
├── 元能力（对自身行为的管控）
│   ├── 自我纠错与反思
│   ├── 不确定性处理
│   ├── 安全与权限意识
│   └── 并发与优先级管理
└── 高级能力（复杂协作与进化）
    ├── 多Agent协作
    └── 自适应学习
```

> **关于"工具调用"的特别说明**
>
> 在 OpenClaw 这类 agent 中，文件读写、Web 检索、调用 API、执行命令，**底层都是一次工具调用**。因此"工具调用"不是与"信息检索""代码生成"等并列的某一类任务能力，而是它们共同的**实现底座**——几乎所有与外部世界交互的能力都通过工具调用落地。故将其归入**基础能力**，与指令遵循、输出格式等底层通用能力并列。
>
> 为避免分类轴混淆，需明确 `tool_usage` 的考察边界：
> - 它**单独考察**的是工具调用这个**动作本身的质量**（选对工具、参数构造正确、读懂返回、失败重试/换路、多工具编排），而**不考察**任务领域的结果质量。
> - 任务的领域结果质量由各自的能力维度负责（如检索结果好坏归 `information_retrieval`，代码正确性归 `code_generation`）。
> - 因此一个外部交互型任务通常会**同时**触发 `tool_usage`（动作质量）和某个领域能力（结果质量），二者正交、可独立评分。
>
> **划分准则**：判断一个维度是否为独立能力，可假设"工具调用动作完美无误"，再看该维度是否还剩下需要考察的内核——若剩下大量认知/编排工作（如 `information_retrieval` 的检索策略与信息综合），则为独立能力；若几乎不剩（如单纯的文件读写），则它只是 `tool_usage` 的一个应用实例，不单独立维度。

## 能力维度详细定义

### 一、基础能力

#### 1. 指令遵循与约束理解

- **标签**: `instruction_following`
- **定义**: Agent 能否准确理解复杂指令中的约束条件、格式要求和边界限定
- **子能力**:
  - 格式约束遵循：按指定格式（列表、表格、分段等）输出
  - 多条件约束：同时满足多个限制条件
  - 角色定位：按指定角色身份行事
  - 边界条件理解：识别"不要做什么"的限制
  - 输出范围限定：控制输出长度、主题范围

#### 2. 上下文记忆与状态管理

- **标签**: `context_memory`
- **定义**: 在多轮交互中保持上下文一致性、正确更新和调用历史信息
- **子能力**:
  - 历史对话回溯：引用先前对话中的信息
  - 跨轮次状态保持：多轮对话中保持一致性
  - 信息积累与更新：随对话推进更新认知
  - 去重比对：识别新旧信息差异

#### 3. 输出格式适配

- **标签**: `output_format`
- **定义**: 根据要求生成指定格式的输出内容
- **子能力**:
  - JSON格式输出：生成合法JSON结构
  - Markdown格式：使用正确的Markdown语法
  - 表格输出：生成结构化表格
  - 文件格式生成：生成ICS、SQL、CSV等特定文件格式
  - 结构化模板：按指定模板填充内容

#### 4. 幻觉抑制

- **标签**: `hallucination_resistance`
- **定义**: 避免编造不存在的事实、数据、API或文件路径
- **子能力**:
  - 事实核验：确认信息真实性后再输出
  - 来源标注：标明数据和结论的出处
  - 数据溯源：追溯数据的原始来源
  - 不确定性声明：对不确定的信息明确标注
  - 拒绝编造：信息不足时拒绝猜测

#### 5. 工具调用

- **标签**: `tool_usage`
- **定义**: 正确选择、调用工具并处理返回结果。作为底层通用能力，它考察的是**工具调用动作本身的质量**（选得对、调得对、错了能恢复），而非任务领域的结果好坏。
- **底座关系**: 文件读写、Web检索、API调用、命令执行等在底层均为工具调用。这些任务在评测时会**同时**触发 `tool_usage`（动作质量）与对应的领域能力（如 `information_retrieval`、`service_integration`、`code_generation` 的结果质量），二者正交、分别评分。
- **不单独立维度的实例**: 单纯的文件读写区分度极低（假设工具调用完美后几乎不剩可考察的内核），不单列为能力——其动作质量归本维度，产出物的格式/落盘正确性归 `output_format`。
- **子能力**:
  - 工具发现：识别可用工具及其功能
  - 工具选择：根据任务需求选择合适的工具
  - 参数构造：正确传递参数并执行调用
  - 结果规整：对工具返回结果进行整理和格式化
  - 失败恢复：调用失败后重试或切换备选方案
  - 多工具编排：组合多个工具完成复杂任务
  - 技能调用：调用已安装的技能/插件

### 二、感知能力

#### 6. 多模态感知

- **标签**: `multimodal_perception`
- **定义**: 处理和理解图片、音频、视频等非文本输入
- **子能力**:
  - 图片理解：识别图片内容和含义
  - OCR识别：从图片中提取文字信息
  - 图表解读：理解图表数据和趋势
  - 音视频处理：处理音频或视频内容

#### 7. 数据提取与处理

- **标签**: `data_extraction`
- **定义**: 从非结构化/半结构化数据中提取、整理和转换关键信息
- **子能力**:
  - 关键信息提取：从文本中定位核心信息
  - 数据聚合：合并多源数据
  - 分类标注：对信息进行分类和标签化
  - 趋势提取：识别数据中的变化趋势
  - 条件筛选：按条件过滤数据
  - 数据清洗：处理缺失值、异常值、格式统一

#### 8. 信息检索与综合

- **标签**: `information_retrieval`
- **定义**: 围绕目标构造检索策略、甄别多源信息并综合成可用结论。本能力考察的是**检索策略与信息综合的质量**（搜什么、信不信、如何整合），而非发起检索这一动作本身——后者的动作质量归 `tool_usage` 考察。
- **底座依赖**: 实际执行时通过 `tool_usage`（web_search / web_fetch / API 等）落地，评测时通常同时触发 `tool_usage`（动作质量）与本维度（结论质量），二者正交。
- **子能力**:
  - 查询构造：将信息需求转化为有效的检索式/关键词
  - 多源聚合：从多个来源收集并合并信息
  - 来源验证：判断信息来源的可靠性，甄别可信度
  - 信息筛选：从大量结果中筛选出真正相关的内容
  - 增量检索：识别新增信息与已有信息的差异
  - 时效性判断：判断检索到的信息是否为最新、是否过时

### 三、认知能力

#### 9. 多步推理

- **标签**: `multi_step_reasoning`
- **定义**: 将复杂问题分解为多个推理步骤并按逻辑链推进
- **子能力**:
  - 因果推理：分析原因和结果的关系
  - 多条件分析：综合多个条件进行判断
  - 趋势判断：基于数据推断发展方向
  - 对比分析：比较多个对象的异同
  - 逻辑编排：按逻辑顺序组织推理过程
  - 跨学科推理：结合多个领域知识进行推理

#### 10. 规划与任务分解

- **标签**: `planning`
- **定义**: 面对复杂目标，自主制定执行计划并分步实施
- **子能力**:
  - 步骤规划：制定有序的执行步骤
  - 多任务并行：识别可并行执行的子任务
  - 优先级排序：判断任务的轻重缓急
  - 异常处理规划：预设失败时的备选方案
  - 流程编排：设计完整的工作流程

#### 11. 领域推理

- **标签**: `domain_reasoning`
- **定义**: 在特定垂直领域**运用**专业知识进行推理和判断。本能力考察的是"会不会用"领域知识做出正确分析（术语理解、规则应用、边界遵循），而非"是否拥有"知识本身（后者属于模型预训练能力）。
- **子能力**:
  - 专业术语理解：正确理解并恰当使用领域术语（金融、医学、法律等）
  - 领域规则应用：将行业标准、规范、最佳实践应用于具体判断
  - 领域约束遵循：遵守特定领域的边界（如医疗免责、金融风险提示、合规要求）
  - 专业逻辑推理：按领域内的因果/论证逻辑进行分析（如财务比率分析、医学鉴别诊断）
  - 跨领域类比：将一个领域的知识或方法迁移到另一个领域

### 四、执行能力

#### 12. 代码生成与理解

- **标签**: `code_generation`
- **定义**: 编写、理解、重构和调试代码
- **子能力**:
  - SQL编写：编写数据库查询和DDL语句
  - 脚本编写：编写Shell、Python等自动化脚本
  - 应用开发：开发完整的应用程序
  - 架构设计：设计系统和模块架构
  - 算法实现：实现特定算法逻辑
  - 代码调试：定位和修复代码问题

#### 13. 外部服务集成

- **标签**: `service_integration`
- **定义**: 在多个第三方服务/平台之间编排数据与状态流转。本能力考察的是**跨服务编排与协议理解**（流程怎么串、状态怎么传），而非单次 API 调用动作——后者归 `tool_usage` 考察。
- **底座依赖**: 实际通过 `tool_usage` 发起各服务调用，评测时常同时触发 `tool_usage`（动作质量）与本维度（编排质量）。
- **子能力**:
  - API调用：调用外部REST/GraphQL接口
  - 第三方平台对接：与Google Workspace、GitHub等平台交互
  - 消息推送：向企业微信、邮件等渠道发送消息
  - 跨服务协调：在多个外部服务间传递数据和状态

#### 14. 自然语言生成

- **标签**: `text_generation`
- **定义**: 生成高质量、符合场景要求的文本内容
- **子能力**:
  - 结构化报告：生成有层次的分析报告
  - 摘要生成：对长文本进行精炼总结
  - 商务文书：撰写邮件、公函等正式文档
  - 演讲稿：撰写会议发言、开幕词等
  - 创意写作：博客、文案、故事等创作
  - 多语言输出：按要求使用不同语言输出

### 五、元能力

#### 15. 自我纠错与反思

- **标签**: `self_correction`
- **定义**: 执行出错后能识别错误、调整策略并重试
- **子能力**:
  - 执行状态确认：验证操作是否成功完成
  - 结果验证：检查输出是否符合预期
  - 异常处理：遇到错误时采取恢复措施
  - 方案可行性验证：评估方案是否可执行
  - Bug排查：定位和修复问题根因

#### 16. 不确定性处理

- **标签**: `uncertainty_handling`
- **定义**: 信息不足时能主动提问或做出合理假设
- **子能力**:
  - 主动澄清：信息不足时向用户提问
  - 假设声明：明确标注推理中的假设前提
  - 置信度标注：对结论的确定程度进行标注
  - 信息不足识别：识别何时缺乏足够信息做判断

#### 17. 安全与权限意识

- **标签**: `safety_awareness`
- **定义**: 识别危险操作、遵守权限边界、避免有害输出
- **子能力**:
  - 投资风险提示：金融场景中明确风险边界
  - 健康安全边界：医疗场景中声明不替代医生诊断
  - 合规约束：遵守法规和行业合规要求
  - 医学伦理：涉及医疗时遵循伦理原则
  - 权限边界：不执行超出授权范围的操作

#### 18. 并发与优先级管理

- **标签**: `concurrency_management`
- **定义**: 面对多个子任务时合理安排执行顺序和优先级
- **子能力**:
  - 多任务调度：合理安排多个任务的执行顺序
  - 优先级判断：识别任务的紧急和重要程度
  - 资源分配：合理分配时间和计算资源

### 六、高级能力

#### 19. 多Agent协作

- **标签**: `multi_agent`
- **定义**: 多个Agent之间进行角色分工和协调配合
- **子能力**:
  - Team模式：启动和管理多Agent团队
  - 角色分工：为不同Agent分配专业角色
  - 任务分配：将复杂任务分配给合适的Agent
  - 协调沟通：管理Agent之间的信息传递和协作

#### 20. 自适应学习

- **标签**: `adaptive_learning`
- **定义**: 从用户反馈和历史交互中调整和改进行为
- **子能力**:
  - 反馈整合：根据用户反馈调整输出
  - 偏好适应：学习并适应用户的工作风格
  - 经验积累：记住有效的解决模式并复用
